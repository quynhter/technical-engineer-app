# Веб-приложение для ведения ИТД

Веб-интерфейс — основной способ работы. Интерфейс использует Astryx 0.7.15 из `app/frontend/src`. Реестр ИД (`registry.jsx`), исходные файлы (`source-files.jsx`), списки схем/документов/ресурсов/фактов/ЖВК/ЖПК (`project-records.jsx`), работы (`work-records.jsx`), остальные таблицы ОЖР (`journal-records.jsx`), проверка/сдача (`workflow-records.jsx`) и ручное ведение (`manual-records.jsx`) работают через `/api/v1/`. Готовая сборка и действующие контроллеры native форм, версий, файлов, настроек и знаний находятся в `app/itd/web_assets`. Структура форм и таблиц исходных документов сохраняется. Старые заменённые списки и скрытая шапка удалены после проверки и подтверждений пользователя. После правок React выполняй сборку из `app/frontend`. Старый код раздела удаляется после проверки и подтверждения пользователя. Python CLI в `app/itd` использует те же инструменты и SQLite. Для работы с ИИ используй навыки в `ai/skills/` и штатные команды CLI. При вызове CLI из чата перед подкомандой указывай `--agent`, чтобы операция отразилась в `logs/ai.log`. Перед изменением деловых данных уточни активную БД и объект. Если пользователь переключил БД в настройках, передавай её путь явно через `--db`.

Для обработки исходных данных и ведения ИТД, включая проверку нормативных оснований, выпуск и комплектацию, используй [ai-technical-engineer](ai/skills/ai-technical-engineer/SKILL.md). Навык поддерживает отдельные поручения и полный цикл в пределах задания пользователя.

- Код и миграции находятся в `app/itd`, готовые шаблоны в `app/templates`, определения полей в `app/forms`. Каталог связывает код формы, шаблон и поля.
- [Ассистент](ai/docs/assistants.md): панель Astryx, миграция 3 accounts (assistants/threads/messages). Чаты принадлежат пользователю и выбранной БД; чужие недоступны даже администратору. Ассистенты используют все инструменты реестра в пределах текущей роли и всю базу знаний, включая новые наборы. Навык — ссылка/версия, без молчаливой замены в старом чате. Ключи LLM только в конфигурации сервера; сообщения/результаты/ключи не журналируются. SSE читает сохранённые снимки, обрыв не отменяет генерацию. Контекст раздела получай инструментами чтения.
- HTTP и CLI вызывают `app/itd/services`: контекст БД/дерева, доверенный актор, общие права и безопасный аудит. Для новых внешних вызовов используй сервисные входы; низкоуровневые функции с SQLite connection не заменяют авторизацию. Локальный CLI сохраняет полномочия учётной записи ОС с доступом к файлам; `--agent` сохраняется и задаёт источник `cli-agent`, журнал `logs/ai.log` прежний.
- MCP по HTTP: [запуск и контракт](ai/docs/mcp.md). Единый реестр `app/itd/tools` задаёт схемы, роли и сервисные вызовы; первый релиз — только чтение. БД фиксируется при запуске `app/itd/mcp_server.py`, входы инструментов не принимают пути БД. Bearer проверяется заново; аудит source=mcp с версиями знаний/навыков — только в read_events отдельной `<база>.audit.sqlite3`. При ошибке аудита результат не выдаётся. Не включай отладочное журналирование SDK с телами запросов.
- Утверждённые девять контрактных пунктов проверяет `development/tests/test_agent_contract.py` в discover. Манифест `ai/knowledge-integrity.sha256` проверяет все файлы знаний, включая бинарные оригиналы; при отсутствии, повреждении или LFS-указателе остановись. Не пересоздавай манифест ради успешной проверки. Изменения его ожидаемых хешей требуют согласованного изменения исходников и объяснения относительно эталона.
- Полная карта таблиц, колонок, источников полей и шаблонов — [MAP.md](ai/MAP.md). При изменении этих связей запускай `PYTHONPATH=app development/.venv/bin/python development/scripts/audit_relationships.py --write-map` и проверяй отмеченные в карте ограничения.
- Добавляй миграции последовательно. Учитывай БД, созданные предыдущими версиями. Оригиналы храни в архиве рядом с БД, а документы выпускай штатными командами, которые регистрируют версии и проверяют хеши. Для путей вне проекта используй полный путь.
- Просмотр не меняет ни одной таблицы деловой БД, включая `audit_events`. Файловые журналы с безопасными метаданными, производный `knowledge.db` и явно запрошенные выходные файлы разрешены. Аудит экспорта и скачивания ZIP хранится рядом с выбранной БД в `<база>.audit.sqlite3`; без успешного аудита ZIP не выдаётся. Создание карточки документа, восстановление файлов и загрузка в очередь импорта — явные действия редактора.
- Права проверяет сервер. Для наблюдателя разрешай чтение, а для редактора также запись и выпуск. Действия с пользователями и рабочими путями требуют администратора. Коды входа, сеансы и содержимое документов не записывай в логи.
- Токены API хранятся SHA-256 в api_tokens отдельной БД аккаунтов (миграция 2 после persistent_sessions). Пользователь создаёт/отзывает свои токены в профиле, администратор просматривает/отзывает все. Открытый токен выдаётся один раз; не сохраняй его в логах. Authorization: Bearer использует текущую роль на каждом запросе, смена роли отзывает токены, удаление пользователя удаляет их каскадно. Не путай токены API с сеансами X-ITD-Token.
- Для всплывающих окон используй `workspace-dialog` и `createWorkspaceDialog`. Формы и списки используют общие классы и компонент `enhanceSelect`. Проверяй обе темы и клавиатурное управление.
- Таблицы просмотра оформляй через `journalTable` и общий `enhanceDataTable`: единые поиск, настройки столбцов, изменение ширины и подвал с пагинацией. Фильтры дат и другие условия размещай в раскрывающемся блоке «Фильтр», в том числе для пустых таблиц. Не добавляй повторные счётчики и отдельные элементы под общим подвалом; дополнительные инструменты располагай над таблицей. Формы ввода и таблицы исходного документа сохраняют свою структуру.
- Для PDF нормативов используй `ai/skills/construction-norm-parser`, для исходных бланков — `ai/skills/doc-template-generator`. Сохраняй связь с оригиналом. Проверка индекса не заменяет сверку нормы с оригиналом и согласование её применимости.
- Тесты запускай командой `PYTHONPATH=app development/.venv/bin/python -m unittest discover -s development/tests -v`. Проверяй смену БД и запись только на тестовых файлах. Веди изменения в корневом `CHANGELOG.md`.

- Исходники и сборка React находятся в `app/frontend/`, запуск — `run.py`, контейнер — корневой `Dockerfile`. `development/` содержит только тесты, инструменты и материалы разработки; работа приложения не зависит от этой папки; знания, навыки, документация и карта — в `ai/`. Кнопки используют общие варианты Astryx. В авторских подписях интерфейса разделяй сведения двоеточием, точкой или кавычками «».
