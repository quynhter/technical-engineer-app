# Веб-приложение для ведения ИТД

Веб-интерфейс — основной способ работы. Интерфейс использует Astryx 0.7.15 из `app/frontend/src`. Реестр ИД (`registry.jsx`), исходные файлы (`source-files.jsx`), списки схем/документов/ресурсов/фактов/ЖВК/ЖПК (`project-records.jsx`), работы (`work-records.jsx`), остальные таблицы ОЖР (`journal-records.jsx`), проверка/сдача (`workflow-records.jsx`) и ручное ведение (`manual-records.jsx`) работают через `/api/v1/`. Готовая сборка и действующие контроллеры native форм, версий, файлов, настроек и знаний находятся в `app/itd/web_assets`. Структура форм и таблиц исходных документов сохраняется. Старые заменённые списки и скрытая шапка удалены после проверки и подтверждений пользователя. После правок React выполняй сборку из `app/frontend`. Старый код раздела удаляется после проверки и подтверждения пользователя. Python CLI в `app/itd` использует те же инструменты и SQLite. Для работы с ИИ используй навыки в `skills/` и штатные команды CLI. При вызове CLI из чата перед подкомандой указывай `--agent`, чтобы операция отразилась в `logs/ai.log`. Перед изменением деловых данных уточни активную БД и объект. Если пользователь переключил БД в настройках, передавай её путь явно через `--db`.

Для обработки исходных данных и ведения ИТД, включая проверку нормативных оснований, выпуск и комплектацию, используй [ai-technical-engineer](skills/ai-technical-engineer/SKILL.md). Навык поддерживает отдельные поручения и полный цикл в пределах задания пользователя.

- Код и миграции находятся в `app/itd`, готовые шаблоны в `app/templates`, определения полей в `app/forms`. Каталог связывает код формы, шаблон и поля.
- HTTP и CLI вызывают `app/itd/services`: контекст БД/дерева, доверенный актор, общие права и безопасный аудит. Для новых внешних вызовов используй сервисные входы; низкоуровневые функции с SQLite connection не заменяют авторизацию. Локальный CLI сохраняет полномочия учётной записи ОС с доступом к файлам; `--agent` сохраняется и задаёт источник `cli-agent`, журнал `logs/ai.log` прежний.
- Утверждённые девять контрактных пунктов проверяет `app/tests/test_agent_contract.py` в discover. Манифест `app/knowledge-integrity.sha256` проверяет все файлы знаний, включая бинарные оригиналы; при отсутствии, повреждении или LFS-указателе остановись. Не пересоздавай манифест ради успешной проверки. Изменения его ожидаемых хешей требуют согласованного изменения исходников и объяснения относительно эталона.
- Полная карта таблиц, колонок, источников полей и шаблонов — [MAP.md](MAP.md). При изменении этих связей запускай `PYTHONPATH=app .venv/bin/python app/scripts/audit_relationships.py --write-map` и проверяй отмеченные в карте ограничения.
- Добавляй миграции последовательно. Учитывай БД, созданные предыдущими версиями. Оригиналы храни в архиве рядом с БД, а документы выпускай штатными командами, которые регистрируют версии и проверяют хеши. Для путей вне проекта используй полный путь.
- Просмотр не меняет ни одной таблицы деловой БД, включая `audit_events`. Файловые журналы с безопасными метаданными, производный `knowledge.db` и явно запрошенные выходные файлы разрешены. Аудит экспорта и скачивания ZIP хранится рядом с выбранной БД в `<база>.audit.sqlite3`; без успешного аудита ZIP не выдаётся. Создание карточки документа, восстановление файлов и загрузка в очередь импорта — явные действия редактора.
- Права проверяет сервер. Для наблюдателя разрешай чтение, а для редактора также запись и выпуск. Действия с пользователями и рабочими путями требуют администратора. Коды входа, сеансы и содержимое документов не записывай в логи.
- Для всплывающих окон используй `workspace-dialog` и `createWorkspaceDialog`. Формы и списки используют общие классы и компонент `enhanceSelect`. Проверяй обе темы и клавиатурное управление.
- Таблицы просмотра оформляй через `journalTable` и общий `enhanceDataTable`: единые поиск, настройки столбцов, изменение ширины и подвал с пагинацией. Фильтры дат и другие условия размещай в раскрывающемся блоке «Фильтр», в том числе для пустых таблиц. Не добавляй повторные счётчики и отдельные элементы под общим подвалом; дополнительные инструменты располагай над таблицей. Формы ввода и таблицы исходного документа сохраняют свою структуру.
- Для PDF нормативов используй `skills/construction-norm-parser`, для исходных бланков — `skills/doc-template-generator`. Сохраняй связь с оригиналом. Проверка индекса не заменяет сверку нормы с оригиналом и согласование её применимости.
- Тесты запускай командой `PYTHONPATH=app .venv/bin/python -m unittest discover -s app/tests -v`. Проверяй смену БД и запись только на тестовых файлах. Веди изменения в корневом `CHANGELOG.md`.
