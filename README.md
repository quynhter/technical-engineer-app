# technical-engineer-app

<img src="app/itd/web_assets/logo.svg" alt="Логотип ИТД: шестерёнка и циркуль" width="80" height="80">

Версия **0.4.0**.

Локальное веб-приложение для ведения исполнительной технической документации. В нём можно вести объекты и разделы, учитывать работы и материалы, выпускать акты и ведомости и искать сведения в нормативной базе.

## Первый запуск

Из корня проекта установите зависимости и запустите сервер. Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r app/requirements.txt
.venv/bin/python -m app.itd web --no-browser
```

При первом запуске сервер создаст чистую `db/itd.db` и выведет ссылку вида `http://127.0.0.1:8765/#КОД` с кодом первого администратора. Откройте ссылку, затем укажите имя и фамилию в профиле. Сохраните код. При следующих запусках приложение показывает адрес, а войти можно по сохранённому коду или ссылке. Если адрес изменился, вставьте код на странице входа.

Для смены пароля:

```bash
.venv/bin/python - <<'PY'
from app.itd.accounts import Accounts

accounts = Accounts("db/itd.db.accounts.sqlite3")
admins = [user for user in accounts.list() if user["role"] == "admin"]
if len(admins) != 1:
    raise SystemExit("Для сброса нужно явно выбрать администратора.")
admin_id = admins[0]["id"]
print(accounts.rotate(admin_id, admin_id)["code"])
PY
```

Круглая кнопка с инициалами расположена справа от переключателя темы. Из профиля можно изменить имя, сменить код и выйти. После смены кода скопируйте новый из окна подтверждения. Другие сеансы этой учётной записи завершатся.

| Роль | Возможности |
| --- | --- |
| Администратор | Работа с ИТД, управление пользователями и рабочими путями |
| Редактор | Просмотр, внесение сведений, выпуск и скачивание документов |
| Наблюдатель | Просмотр сведений, предпросмотр актов и поиск по нормативам |

Администратор добавляет пользователя в профиле и передаёт ему индивидуальную ссылку или код. Изменение роли и удаление завершают действующие сеансы выбранного пользователя. Собственную роль или удаление своего аккаунта выполняет другой администратор. Сервер слушает локальный адрес `127.0.0.1`. Учётные записи позволяют разделять доступ к одному запущенному приложению.

## Рабочая и тестовая базы

В профиле администратора введите абсолютный путь к существующему файлу `.db` и путь к папке ИТД. Папка может быть на другом диске. Если её пока нет, приложение создаст её внутри существующего родительского каталога. Новые файлы попадут в выбранное дерево. Уже выпущенные документы и оригиналы остаются по зарегистрированным путям. Для удаления файлов через проверку папок дерево ИТД и БД должны быть на одном томе.

Чтобы подготовить чистую тестовую БД, выполните `.venv/bin/python -m app.itd --db db/test.db init`. Выделите ей отдельную папку ИТД. Приложение проверит, что её дерево не пересекается с деревом другой подключавшейся БД. Переключение рабочих путей завершает сеансы остальных пользователей и сохраняется при перезапуске. Учётные записи остаются в `db/itd.db.accounts.sqlite3` для запуска по умолчанию. Явный `--db` при запуске сервера использует отдельное хранилище настроек и учётных записей рядом с этим файлом.

## Работа с ИИ

Откройте корень проекта в агенте и передайте ему задачу и путь к используемой БД. Веб-приложение показывает справочник и работает с локальными файлами. Обработку PDF нормативов и подготовку новых шаблонов выполняет агент в чате.

- [ai-technical-engineer](skills/ai-technical-engineer/SKILL.md) ведёт ИТД от разбора исходных данных и проверки применимых требований до журналов, актов и готового комплекта. Можно поручить отдельную операцию или весь цикл. Например: «Прочитай skills/ai-technical-engineer/SKILL.md, проверь исходные данные выбранного раздела и подготовь комплект к выдаче». Укажите БД, объект, раздел и нужную стадию; реальные подписи и приёмка требуют подтверждённых оснований. Навык не содержит записей конкретных объектов.

- [construction-norm-parser](skills/construction-norm-parser/SKILL.md) преобразует нормативы в проверяемые материалы для `app/knowledge`. Индекс поиска строится из этих материалов.
- [doc-template-generator](skills/doc-template-generator/SKILL.md) подготавливает шаблоны из ваших исходных бланков. Готовые шаблоны лежат в `app/templates`, настройки полей — в `app/forms`.

Список команд доступен через `.venv/bin/python -m app.itd --help`. Если в веб-интерфейсе выбрана другая БД, передавайте её агенту явно через `--db /абсолютный/путь.db` перед подкомандой.

В `logs/db.log` записываются серверные операции с БД. В `logs/ai.log` попадают обращения веб-приложения к нормативной базе и вызовы CLI с флагом `--agent`. Переписка с внешним ИИ хранится в его чате.


## Состав репозитория

Публикуются исходники, миграции, определения форм и готовые шаблоны. Папки `ИТД` и `ИТД_тест`, рабочие базы, архивы выпущенных документов, журналы и локальные настройки в репозиторий не входят. При первом запуске создаётся чистая рабочая база.
