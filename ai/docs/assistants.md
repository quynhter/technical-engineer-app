# Встроенный ассистент

Кнопка «Ассистент» находится под «Все объекты» в секции «Инструменты».
Она видна при наличии активного ассистента с настроенным провайдером.
Чат открывается справа без перехода; на узком экране занимает рабочую область.
Enter открывает/отправляет, Shift+Enter переносит строку, Escape закрывает.
Закрытие панели не отменяет генерацию; «Стоп» отменяет явно.

## Настройка в браузере

В профиле администратора откройте «Настроить ассистентов», затем «Подключения к моделям».
Выберите готовый провайдер или задайте собственное имя, протокол и адрес API.
Введите ключ или явно включите подключение без ключа для локального сервиса.
После «Сохранить подключение» выберите его в карточке ассистента, укажите модель,
инструкцию, затем сохраните ассистента. Все инструменты и вся база знаний подключаются автоматически. Перезапуск не нужен.

Подключения сохраняются в `<accounts>.llm-providers.json` рядом с хранилищем accounts,
с правами 0600 и атомарной заменой файла. Они относятся к экземпляру сервера,
сохраняются при смене рабочей БД. Пустой ключ при редактировании сохраняет прежний.
Ключ передаётся в запросе сохранения и не возвращается браузеру; форма очищает
поле после сохранения. Конфигурация из браузера имеет приоритет над серверными профилями.
Редактор и наблюдатель не могут читать настройки подключений или менять их.

## Дополнительная настройка сервера

Поддерживаются OpenAI Chat Completions и совместимые сервисы, Anthropic Messages,
Gemini streamGenerateContent. Идентификатор модели задаётся свободно: выбирайте
модель с потоковым выводом и вызовами функций. Автоматической подмены модели нет.
Встроенные профили: openai, anthropic, gemini, deepseek, groq, openrouter, xai,
mistral, ollama. Соответствующие переменные окружения с ключами:
OPENAI_API_KEY, ANTHROPIC_API_KEY, GEMINI_API_KEY, DEEPSEEK_API_KEY,
GROQ_API_KEY, OPENROUTER_API_KEY, XAI_API_KEY, MISTRAL_API_KEY, OLLAMA_API_KEY.

Собственный сервис и переопределение встроенных адресов задаются серверным JSON.
Укажите его абсолютный путь в ITD_LLM_CONFIG перед запуском веб-сервера.
Пример — [app/llm-providers.example.json](../../app/llm-providers.example.json).
protocol: chat, anthropic либо gemini; base_url: адрес без конечного endpoint;
api_key_env: имя переменной окружения с ключом. allow_anonymous явно включает
сервис без ключа (например, собственный Ollama/vLLM/LM Studio).
Без ключа либо allow_anonymous профиль недоступен. Ключи не передаются
в браузер, URL, SQLite или логи. HTTP redirects и прокси окружения не используются.

В профиле администратора нажмите «Настроить ассистентов»: имя, инструкция,
провайдер, модель,
ссылка на SKILL.md и активность. Ключ задаётся в отдельном блоке подключений. Используется вся база знаний; поиск не ограничен отдельным набором.
Список инструментов также подключается целиком и проверяется по роли при каждом вызове.
Это действует для старых карточек с сохранёнными подмножествами без записи при чтении.
Новые карточки сохраняют весь реестр и knowledge_bases=["*"].

## Права, контекст, версии

Ассистенту автоматически доступны все инструменты реестра в пределах текущей роли пользователя.
Проверка повторяется перед каждым вызовом общим реестром. Первый реестр — только
чтение. Инструкция и JSON модели дополнительных полномочий не дают.
Сведения раздела приходят инструментами: в системном промпте только инструкция,
ссылка/текст выбранного навыка и object_id/project_id, без копии деловых данных.
Документы и результаты инструментов — данные, не инструкции.

Навык хранится ссылкой и SHA-256 набора skills/ с references. Текст читается
при запуске ответа, не копируется в настройки/threads. Новые чаты получают
текущую версию, старые сохраняют прежнюю. Если прежних файлов уже нет, история
читается, но продолжение требует нового чата; молчаливой замены версии нет.
Контекст чата закреплён при создании, смена раздела не перепривязывает историю.

История, поток и отмена доступны только владельцу в выбранной БД. Администратор
настраивает ассистентов, но не читает чужие чаты. Путь БД API не принимает.
Сеанс, рабочее пространство, активность и права проверяются перед каждым
запросом к провайдеру и инструментом. Ключи находятся только на сервере.

## Хранение и поток

Последовательная миграция 3 accounts создаёт assistants, threads, messages.
Деловая схема 001–023 не меняется. Просмотр истории/SSE не пишет деловые данные;
отправка явно записывает личную историю accounts. Вызовы инструментов имеют
source=assistant, версии и отдельный read_events sidecar. Текст сообщений,
результаты и ключи в файловые логи не попадают.

Сначала сохраняются запрос и ответ running, затем запускается фоновая задача.
Частичный текст, полные вызовы и результаты сохраняются по мере прихода.
SSE передаёт снимки сохранённых сообщений: переподключение не удваивает текст.
Обрыв SSE не отменяет ответ. Перезапуск отмечает незавершённые ответы interrupted,
сохраняя текст. Повторный request_key не создаёт второй запрос. Автоматических
повторов LLM нет. Лимиты: 12 раундов, 16 вызовов/раунд, 200000 символов ответа;
таймаут/лимит/ошибка сохраняют полученную часть. Отмена явная.

## HTTP API

- GET /api/v1/assistants — доступные активные ассистенты;
- GET /api/v1/assistant/admin — настройки администратора и реестр;
- POST /api/v1/assistant/provider — подключение провайдера (admin);
- POST /api/v1/assistant/config — создание/обновление (admin);
- GET/POST /api/v1/assistant/threads — личный список/создание;
- GET /api/v1/assistant/thread?thread_id=ID — история;
- POST /api/v1/assistant/messages — thread_id, text, request_key;
- GET /api/v1/assistant/events?thread_id=ID&message_id=ID — SSE;
- POST /api/v1/assistant/cancel — thread_id;
- POST /api/v1/assistant/thread-title — thread_id, title (только владелец);
- POST /api/v1/assistant/thread-delete — thread_id; отказ, пока ответ формируется.

Применяются действующие X-ITD-Token/Bearer, серверные права и Host/Origin.
Сервер передаёт сообщения и результаты разрешённых инструментов выбранному LLM.
Внешняя передача документов, Ф.И.О. и реквизитов для этого внедрения согласована
пользователем. Локальный провайдер также поддерживается.

Официальные протоколы:
[OpenAI](https://developers.openai.com/api/docs/guides/function-calling),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming),
[Gemini](https://ai.google.dev/api/generate-content).
Фиктивные потоки проверяют адаптеры, но не доступность конкретных внешних
моделей/аккаунтов. Реальные ключи для автоматических и ручных UI-тестов не нужны.

К сообщению можно прикрепить до четырёх файлов общим размером до 4 МиБ. Поддерживаются PDF с текстовым слоем, DOCX, XLSX и файлы UTF-8 (TXT, MD, CSV, TSV, JSON). Имена файлов и извлечённый текст (до 80 000 символов на сообщение) сохраняются в личной истории чата и передаются настроенной модели.
