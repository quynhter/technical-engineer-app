# MCP: инструменты чтения ИТД

Этап 4. Официальный Python SDK `mcp==2.3.0`, Streamable HTTP, endpoint `/mcp`.
Совместим с закреплёнными FastAPI, Starlette, Pydantic и Uvicorn проекта;
SDK сам обрабатывает согласование версий протокола. Это отдельный процесс
с фиксированной БД: смена БД в веб-настройках не перенаправляет MCP.

## Запуск

Подготовьте БД и аккаунты штатным веб-приложением. Создайте токен API в профиле.
Сервер MCP ничего не инициализирует и не мигрирует. Из корня проекта:

```bash
PYTHONPATH=app development/.venv/bin/python -m itd.mcp_server --agent \
  --db /абсолютный/путь/объект.db \
  --accounts /абсолютный/путь/объект.db.accounts.sqlite3 \
  --itd-root /абсолютный/путь/ИТД --host 127.0.0.1 --port 8766
```

Клиенту задайте URL `http://127.0.0.1:8766/mcp` и заголовок
`Authorization: Bearer <токен>` через защищённые настройки клиента.
Не вставляйте секрет в URL, историю команд или отчёты. X-ITD-Token и код
входа не принимаются. Каждый HTTP-запрос и обработчик инструмента заново
проверяет текущую роль, срок, отзыв и существование владельца.
Host/Origin проверяет SDK. Для сетевого доступа используйте контролируемый
адрес сервера; публикация в интернете требует HTTPS. OAuth-выдача токенов
не предоставляется: используются персональные токены этапа 3.

## Единый реестр

Определения в `app/itd/tools/__init__.py`: имя, описание, модель Pydantic,
роль, класс доступа и сервисный вызов. MCP и будущий ассистент используют
`available` и `invoke`; документационная таблица строится `documentation()`.
В первом релизе инструментов записи нет даже для администратора.
При расширении реестра наблюдатель не получает инструменты записи;
разрешённый список ассистента дополнительно пересекается с ролью пользователя.
Ни один вход не принимает БД, дерево, аккаунты, роль или пользователя.
Неизвестные поля и неверные типы отклоняются без выполнения операции.

`project-check` использует действующий сервисный отчёт готовности/связей;
ничего не исправляет и не заменяет нормативную экспертизу.
`project-records` возвращает то же представление ведомостей/журналов,
которое получает веб-интерфейс. Пути в результатах — сведения, не параметры
выбора БД. Поиск остаётся FTS5 с прежними фильтрами, порядком и полями CLI.

## Ответы и версии

Успех: `data` содержит неизменённый результат сервиса, рядом находятся
`knowledge_version` (fingerprint из knowledge-status), `skills_version`
(SHA-256 имён и содержимого всех Markdown/YAML в skills/) и `index_status`.
MCP возвращает этот объект в structuredContent и JSON-тексте; список tools
содержит версии в `_meta`. CLI knowledge-status и веб `/api/v1/knowledge`
возвращают тот же fingerprint и skills_version через общий сервис.
Все транспорты используют канонический root и knowledge.db рядом с выбранной
БД. Произвольные каталоги знаний через MCP не задаются.

Поиск/show могут штатно подготовить только производный knowledge.db.
Отсутствующий индекс виден как missing; повреждённые/пропавшие исходники,
неверные хеши и LFS-указатели прекращают выполнение до выдачи данных.
Ошибка инструмента возвращает isError и безопасный код; содержимое
аргументов, исключений и документов в сообщении ошибки не отражается.
Если версия не может быть проверена, она явно равна unavailable.

## Аудит и граница чтения

Каждый tools/call (включая ошибку, отказ и неизвестное имя) записывается
в `<база>.audit.sqlite3`, таблицу read_events, с source=mcp, актором,
текущей ролью, поручителем, результатом и версиями. Содержимое запросов,
ответов, документов и токенов не записывается. Для операции без раздела
project_id=0; неизвестное имя заменяется фиксированным unknown-tool.
Три поля версий добавляются последовательно при открытии прежнего sidecar,
старые записи сохраняются. Деловая БД и audit_events не меняются.
При недоступном аудите результат инструмента не выдаётся.
Инициализация, ping и tools/list не читают деловые записи и не создают
события инструмента. Последнее использование токена обновляет только accounts.

Приоритет AGENTS.md применён к противоречию исходного задания 4.7:
аудит чтения находится в sidecar, а не в audit_events деловой БД.

SDK: [официальный репозиторий](https://github.com/modelcontextprotocol/python-sdk),
[низкоуровневый сервер](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/advanced/low-level-server.md).
