# MCP: чтение и предложения изменений ИТД

Официальный Python SDK `mcp==2.3.0`, Streamable HTTP, endpoint `/mcp`.
Совместим с закреплёнными FastAPI, Starlette, Pydantic и Uvicorn проекта;
SDK сам обрабатывает согласование версий протокола. Это отдельный процесс
с фиксированной БД: смена БД в веб-настройках не перенаправляет MCP.

## Запуск

Подготовьте БД и аккаунты штатным веб-приложением. Создайте токен API в профиле.
Сервер MCP ничего не инициализирует и не мигрирует. Из корня проекта:

```bash
PYTHONPATH=app development/.venv/bin/python -m itd.mcp_server --agent \
  --db /абсолютный/путь/объект.db \
  --accounts /абсолютный/путь/объект.db.accounts.sqlite3 \
  --itd-root /абсолютный/путь/ИТД --host 127.0.0.1 --port 8766
```

Клиенту задайте URL `http://127.0.0.1:8766/mcp` и заголовок
`Authorization: Bearer <токен>` через защищённые настройки клиента.
Не вставляйте секрет в URL, историю команд или отчёты. X-ITD-Token и код
входа не принимаются. Каждый HTTP-запрос и обработчик инструмента заново
проверяет текущую роль, срок, отзыв и существование владельца.
Host/Origin проверяет SDK. Для сетевого доступа используйте контролируемый
адрес сервера; публикация в интернете требует HTTPS. OAuth-выдача токенов
не предоставляется: используются персональные токены этапа 3.

## Единый реестр

Определения в `app/itd/tools/__init__.py`: имя, описание, модель Pydantic,
роль, класс доступа и сервисный вызов. MCP и ассистент используют общие
`available` и `invoke`; таблица строится `documentation()`.
Наблюдателю доступны инструменты чтения. Редактор и администратор также
получают инструменты `preview-*` с ролью `editor` и классом `write`.
Ни один вход не принимает БД, дерево, аккаунты, роль или пользователя.
Неизвестные поля и неверные типы отклоняются без выполнения операции.

## Предпросмотр изменений

Инструмент возвращает `data.dry_run`, `preview_id`, раздел, срок, результаты
проверок, предупреждения и фактическую разницу строк. `applicable=false`
означает, что предложение требует исправления или не содержит изменений.
Каждый инструмент задаёт собственную схему строк и операций. Сервер сверяет
предложение на изолированном снимке через сервисы веб-форм. Деловая БД
при подготовке остаётся неизменной.

Для применения войдите в веб-приложение с тем же аккаунтом, выберите
ту же БД и раздел РД, откройте «Предпросмотры изменений» и проверьте
показанные строки. Веб-диалог отправляет идентификатор, хеш и ID раздела.
Хеш действует 30 минут. Старые, использованные и изменившиеся предложения
отклоняются. MCP и Bearer не дают права на применение предложения.
На сервере должна быть применена миграция 025.

`preview-specification` принимает `attachment.name` и
`attachment.content` (base64 исходного файла). Можно передать категорию
и распознанные строки, например для PDF со сложной разметкой. Автоматический
разбор поддерживает табличные XLSX, DOCX и текст с разделителями, а также
массив строк в JSON. В PDF используются строки текстового слоя. Для
вставки нужны позиция, наименование, единица, количество, ссылка на
документ или норму и категория ресурса. Строки с пропусками видны в
предпросмотре и сохраняются как вопросы к спецификации при применении.
Архивируются первоначальные байты с SHA-256. Лимиты на файл и извлечённый
текст составляют 4 МиБ и 80 000 символов.

## Ответы и версии

Успех: `data` содержит неизменённый результат сервиса, рядом находятся
`knowledge_version` (fingerprint из knowledge-status), `skills_version`
(SHA-256 имён и содержимого всех Markdown/YAML в skills/) и `index_status`.
MCP возвращает этот объект в structuredContent и JSON-тексте; список tools
содержит версии в `_meta`. CLI knowledge-status и веб `/api/v1/knowledge`
возвращают тот же fingerprint и skills_version через общий сервис.
Все транспорты используют канонический root и knowledge.db рядом с выбранной
БД. Произвольные каталоги знаний через MCP не задаются.

Поиск/show могут штатно подготовить только производный knowledge.db.
Отсутствующий индекс виден как missing; повреждённые/пропавшие исходники,
неверные хеши и LFS-указатели прекращают выполнение до выдачи данных.
Ошибка инструмента возвращает isError и безопасный код; содержимое
аргументов, исключений и документов в сообщении ошибки не отражается.
Если версия не может быть проверена, она явно равна unavailable.

## Аудит

Каждый вызов инструмента, включая валидацию и отказы, записывается в
`<база>.audit.sqlite3`, таблицу `read_events`, с источником `mcp`, актором,
ролью, результатом и версиями знаний и навыков. Для запроса без раздела
используется `project_id=0`. Успешный предпросмотр имеет `preview_id`.
При ошибке аудита результат не выдаётся. Инициализация, ping и tools/list
не создают событий инструмента. Последнее использование токена
обновляется только в accounts.

Сами предложения хранятся в отдельном `<база>.previews.sqlite3`.
Запись применения с `source=web`, пользователем и версиями сохраняется
в `audit_events` вместе с деловыми строками. Уникальный `preview_id`
в событии служит отметкой однократного применения. Отказы после попытки
веб-подтверждения записываются в `read_events`. Тексты и байты документов,
полные аргументы, сообщения и ключи в события аудита и файловые логи
не записываются.

SDK: [официальный репозиторий](https://github.com/modelcontextprotocol/python-sdk),
[низкоуровневый сервер](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/advanced/low-level-server.md).
