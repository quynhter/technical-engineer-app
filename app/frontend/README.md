# Интерфейс Astryx

Этап 5: assistant.jsx использует ChatMessageList/ChatMessage/ChatMessageBubble,
ChatToolCalls и ChatComposer Astryx 0.7.15, SSE снимки и явную отмену.
Кнопка «Ассистент» под «Все объекты» видна при доступных ассистентах; профиль
администратора открывает настройку и без них. Панель сохраняет страницу,
на узком экране занимает рабочую область; Escape закрывает с возвратом фокуса.
[Конфигурация и контракт](../../ai/docs/assistants.md).

Используется только Astryx 0.7.15, React и локальный bundle. Node.js нужен для пересборки, доступ к CDN при запуске Python-приложения не требуется. Исходники и lockfile включены в репозиторий, node_modules — нет. Лицензии поставляются в design-LICENSE.txt; Open Sans берётся из локальных файлов.

| Просмотр | Источник |
|---|---|
| Реестр ИД, DOCX, ZIP | src/registry.jsx |
| Исходные файлы, несколько файлов/drag-and-drop до32МБ | src/source-files.jsx |
| Схемы, документы, спецификация, факты, ЖВК, ЖПК | src/project-records.jsx |
| Работы ОЖР, выбор для акта, JSON/CSV | src/work-records.jsx, work-table.mjs |
| Титульный лист и остальные таблицы ОЖР | src/journal-records.jsx, journal-model.mjs |
| Проверка/состав комплекта, сдача/замечания | src/workflow-records.jsx, workflow-model.mjs |
| Ручное ведение, ресурсы/поставки/оригиналы/источники | src/manual-records.jsx |

Данные и загрузки этих компонентов проходят через src/api-v1.mjs и /api/v1/. Запросы отменяются на смене контекста; устаревший ответ не заменяет текущий проект. Изменение деловых данных подтверждает сервер с общей сервисной авторизацией. Нет автоматических повторов записи. ZIP называется «ИТД — актуальные файлы.zip», DOCX сохраняет серверное имя. Без успешного аудита read_events в sidecar ZIP не выдаётся.

Заменённые списки и скрытая старая шапка удалены после отдельных подтверждений пользователя. Исключение явно согласовано: incomingJournalBody/incomingJournalTable и filteredEntries остаются для неизменяемого legacy-теста; рабочий интерфейс их не вызывает. Старый тест registry-zip заменён тестами действующего API-компонента. Полный инвентарь и подтверждения — development/work/etap2-inventory.md.

Действующие native формы реквизитов, участников/РД, материалов, входного контроля, версий документов, импорта, файловых операций, профиля и знаний сохраняют свои контроллеры в app/itd/web_assets. Это активные части интерфейса, а не второй вариант заменённых списков. Формы и таблицы исходного документа сохраняют свою структуру. Все диалоги используют createWorkspaceDialog и beforeClose. adapters.jsx связывает DateInput, Collapsible, ClickableCard, Banner и Dialog с native узлами, сохраняя значения и слушатели. Native поля получают полную рамку TextInput/TextArea.

Оболочка design.jsx использует AppShell, SideNav, TopNav, Breadcrumbs и единые Theme/InternationalizationProvider с React-порталами. Удаление страницы не сбрасывает тему. Доступны пять тем: Neutral, Stone, Butter, Gothic, Y2K; светлый/тёмный режим и акцент сохраняются через прямые события. Профиль/сеанс и статус соединения сохраняют DOM identity при смене desktop/mobile. Видимые инструменты: все объекты, ручное ведение, база знаний.

BrowseTable в astryx-tables.jsx использует настоящие Table и плагины Astryx: поиск, фильтрация, сортировка, столбцы, ширина, выбор и пагинация. Условия дат и прочие фильтры находятся внутри общего «Фильтр», включая пустые таблицы. Количественные суммы размещены в общем подвале, разделяются по единицам; порядковые номера не суммируются. Выбранный CSV и снятие выбора сохраняются. Минимальная ширина учитывает заголовок и кнопки; гибкий _gutter позволяет менять последнюю деловую колонку. Предпочтения в itd.astryx.tables.v1 разделены по роли/проекту/рабочему пространству, без деловых данных.

Сборка: npm ci и npm run build из app/frontend. Проверка: npm test (тесты находятся в development/frontend/tests и для обычного запуска не нужны). Результат — app/itd/web_assets/design.js и design.css. Обновление Astryx требует явной пересборки и проверки API. Подробности ручной проверки и финального прогона — development/work/manual-ui-check.md и development/work/etap2-completion.md.

Этап 3: native account.js добавляет в профиль создание/отзыв токенов API и
административный список всех владельцев. Однократный секрет очищается вместе
с prompt-content при закрытии workspace-dialog и не сохраняется в storage.
Список строится через journalTable/enhanceDataTable с общим фильтром и подвалом;
права и отзыв проверяет сервис accounts на сервере. Реальные HTTP-проверки
используют временные файлы; DOM-сценарии api-tokens.test.mjs — обе темы/роли.
