# Локальная нормативная база знаний

Материалы пользователя: И 1.13-07, РД 78.145-93, Приказ №344/пр и СП 77.
Исходные 17 Markdown-разделов и 42 JSONL-правила включены без изменения содержания.
Это подготовленные ИИ выдержки, а не проверенная полная копия нормативов.
Слова «обязательный» и перечни форм в них сохраняются как данные источника.
Редакцию, актуальность и применимость проверяют отдельно по оригиналу.

## Каталог и тексты нормативных документов сайта

В наборе [normativy_ispolnitelnaya](normativy_ispolnitelnaya/README.md) — полный
реестр 105 позиций из шести подразделов Исполнительная.ru и 20 454 поисковые
записи: тексты опубликованных версий, отдельные PDF и изменения, карточки
источников и инструкция агенту. Сохранены оригиналы, таблицы, изображения,
SHA-256 и привязки к пунктам/страницам. Для ТР ЕАЭС 042/2017 восстановлен
официальный архив ЕАЭС вместо недоступной ссылки сайта.

Это архив публикаций для поиска; актуальность и применимость требуют проверки.
Две позиции содержат проекты вместо обозначенных ГОСТов: ГОСТ 7473-2010
сохранен как проект, а для неофициального перевода ISO/FDIS вместо
ГОСТ Р ИСО 9001-2015 добавлена карточка с расхождением без полного текста.
Ошибочные обозначения и даты не исправлены молча, см. catalog.json и issues.json.
Поиск: `--corpus normativy_ispolnitelnaya --kind chunk`. Числовые правила
не генерировались; OCR, формулы и таблицы сверяют с оригиналом.

## Как пользоваться

Агент получает правила поиска из AGENTS.md и сам вызывает команды. Можно написать:

> Найди в базе знаний требования к испытаниям изоляции для нашего раздела.
> Покажи пункт, условия и предложенные формы; проверь применимость по оригиналу.

В веб-интерфейсе кнопка **«База знаний»** открывает поиск по всем наборам, без
обязательного выбора объекта. Полный текст содержит таблицы, условия и метаданные.
Markdown отображается как таблицы, списки и выделенный текст встроенным
рендерером без сторонних библиотек. HTML из нормативов не исполняется.
Хеши и служебные метаданные доступны агенту через CLI; в веб-поиске они скрыты.

Из корня проекта (Windows: Python `app/.venv/Scripts/python.exe`):

```bash
app/.venv/bin/python -m app.itd knowledge-status
app/.venv/bin/python -m app.itd knowledge-validate
app/.venv/bin/python -m app.itd knowledge-index
app/.venv/bin/python -m app.itd knowledge-search --query 'изоляц' --corpus sp77
app/.venv/bin/python -m app.itd knowledge-search --kind rule --clause '6.7.26' --corpus sp77
app/.venv/bin/python -m app.itd knowledge-search --work 'испытания' --form 'Протокол'
app/.venv/bin/python -m app.itd knowledge-show --id 'sp77/rules.jsonl#rule-14'
app/.venv/bin/python -m app.itd knowledge-export --output db/work/knowledge-export.jsonl
```

`--corpus` — имя подпапки: i_1_13_07, rd78_145_93, prikaz_344pr, sp77.
`--kind` — chunk либо rule. `--clause` — точное значение поля clause;
для поиска внутри объединённых пунктов используйте `--query`.
`--work` и `--form` ищут подстроку в поисковых метках, регистр не учитывается.
`--limit` — от 1 до 100, по умолчанию 10. Слова запроса соединяются И,
каждое ищется как начало слова. Для русских окончаний используйте основу
(«изоляц», «испытан»). Это FTS5, без морфологического, векторного и смыслового
поиска. Укороченный запрос и фильтры помогают, если длинная фраза не найдена.

`knowledge-search` возвращает выдержку и полные метаданные, `knowledge-show` —
весь текст. Для обоснования сохраняйте doc_id, clause, источник, SHA-256 и
условия, а не один ID результата: ID зависит от пути и порядкового номера.
Файл/строка — локатор подготовленного материала, а не страница оригинала.
У существующих материалов нет подтверждённой связи со страницами оригиналов.
Разночтения шифра приказа в MD и JSONL сохранены; фильтр corpus объединяет их.

## Хранение и обновление

Исходники — `app/knowledge/<corpus>/*.md` и `*.jsonl`, UTF-8.
README.md служат навигацией и не индексируются. Формат входа и примеры:
[references/format.md](../../app/skills/construction-norm-parser/references/format.md).

Индекс — `db/knowledge.db`, производный кэш SQLite FTS5. При `--db` в другой
папке индекс располагается рядом с указанной БД. Рабочая `db/itd.db` и её
миграции не изменяются. Поиск работает и без рабочей БД. Дополнительных Python
зависимостей, сетевых запросов, ключей API и внешних сервисов нет.
При поиске сравниваются SHA-256 всех входных файлов; изменённый индекс
пересобирается автоматически. Явная `knowledge-index` перестраивает его вручную.
Публикация атомарна: ошибка разбора оставляет прежний индекс на диске, а поиск
возвращает ошибку вместо использования устаревшей версии. Посторонняя БД
не перезаписывается. Пустой вход и ошибочная строка не пропускаются молча.

`knowledge-validate` проверяет формат всех файлов, но не достоверность содержания,
полноту OCR и актуальность норматива. `knowledge-status` показывает состав,
fingerprint и missing/ready/stale/invalid для индекса. `doctor` проверяет FTS5 и
поиск на временном индексе. При переносе сохраняйте исходники, индекс можно
построить заново. Переносимый ZIP включает базу и скилл.

## Добавление нового норматива

Скилл — инструкция для модели о повторяемой работе. Он помогает разобрать
документ, но сам не выполняет OCR или перевод без участия агента.
Проектная версия адаптирована из предоставленного пользователем SKILL.md:
[construction-norm-parser](../../app/skills/construction-norm-parser/SKILL.md).

Установка в локальный каталог обнаружения Codex:

```bash
app/.venv/bin/python app/scripts/install_project_skills.py
```

Скрипт копирует только этот скилл в `.agents/skills/construction-norm-parser`,
не меняет глобальные настройки и не заменяет существующий скилл. После установки
откройте новый чат проекта, если текущий ещё не видит его в списке. Пример вызова:

> $construction-norm-parser Разбери переданный СП для базы знаний этого проекта.

При недоступности каталога скиллов можно написать в Codex или OpenCode:

> Прочитай app/skills/construction-norm-parser/SKILL.md и подготовь этот норматив.

AGENTS.md также указывает этот путь, поэтому инструкция доступна агенту без
установки. Порядок: оригинал и редакция → отдельная staging-папка → пункты,
таблицы, сноски и provenance → структурная проверка → включение нового набора →
поиск. Замена действующего набора сначала согласуется по точному списку изменений.

## Связь с подготовкой ИТД

При выборе форм, планировании контроля и проверке актов агент ищет требования
по конкретной работе, читает полный фрагмент и сверяет первоисточник. Комплект
форм пользователь выбирает отдельно. Проверенные основания можно сохранить в
projects.agent_context и согласованной матрице через штатные CLI-команды.
Поиск не создаёт акты, не назначает подписантов, не заполняет required-поля и
не подтверждает факт монтажа или статические утверждения бланка. Универсального
исполнителя JSONL-правил пока нет: условия и применимость требуют предметного
разбора. Успешный поиск не является нормативной экспертизой.
