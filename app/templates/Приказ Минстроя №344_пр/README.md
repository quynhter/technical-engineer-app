# Акты по предоставленным формам приказа Минстроя №344/пр

Все пять форм используют [единый объектный контракт](../README.md):
`object.name`, `organisations.customer.full_name`,
`representatives.customer_control.position`,
`representatives.customer_control.organisation.inn`, `document.date.year`.
Пути всех полей перечислены в [общем справочнике](../TEMPLATE_FIELDS.md).
Вводимые значения оформлены Times New Roman, полужирным курсивом, как в
примерах заполнения ИД-Просто. Сведения и подписи берутся из выбранного документа.

Подготовлены рабочие копии всех пяти исходников из `misc/downloads/Исходные формы документов/Приказ Минстроя №344_пр`.
Номер, дата и название приказа воспроизводятся из предоставленных файлов; подготовка
шаблонов не является проверкой актуальной редакции нормативного акта.

| Код типа | Назначение |
|---|---|
| МИНСТРОЙ_344_АОСР | Освидетельствование скрытых работ |
| МИНСТРОЙ_344_АООК | Освидетельствование ответственных конструкций |
| МИНСТРОЙ_344_АОУСИТО | Освидетельствование участков сетей инженерно-технического обеспечения |
| МИНСТРОЙ_344_АОГРО | Освидетельствование геодезической разбивочной основы |
| МИНСТРОЙ_344_АРООКС | Разбивка осей объекта капитального строительства на местности |

Эти акты дополняют комплект СП 77, И 1.13-07 или иной выбранный комплект.
Их не следует назначать всем разделам автоматически: состав определяется работами.
Шаблоны находятся в этой папке; поля — в `app/forms/Приказ Минстроя №344_пр`.
Общий каталог `app/templates/catalog.json` содержит пути и SHA-256 исходников.
[ПОЛЯ.md](%D0%9F%D0%9E%D0%9B%D0%AF.md) содержит все поля и карту основных мест заполнения.

## Подключение

```bash
python -m app.itd form-register --type МИНСТРОЙ_344_АОСР --name 'Акт освидетельствования скрытых работ' --group act --fields 'app/forms/Приказ Минстроя №344_пр/МИНСТРОЙ_344_АОСР.fields.json'
```

Для остальных форм используются их коды и JSON из каталога. Подготовка библиотеки
не регистрирует формы в рабочей БД. Перед повторной регистрацией проверяются
существующие настройки типа: `form-register` заменяет общие поля формы.

## Организации и подписанты

| Роль | Назначение |
|---|---|
| customer | Застройщик / технический заказчик / иное лицо, указанное в шапке |
| customer_control | Представитель строительного контроля застройщика/заказчика |
| builder | Лицо, осуществляющее строительство, и его представитель |
| builder_control | Представитель строительного контроля лица, осуществляющего строительство |
| designer | Проектировщик и его представитель по применимости |
| work_performer | Фактический исполнитель работ и его представитель по применимости |
| network_operator | Эксплуатирующая организация и представитель в АОУСИТО |

Организации и подписанты назначаются отдельно. Совпадение роли организации и
подписанта не создаёт назначение автоматически. Один участник может иметь несколько
ролей только по подтверждённым данным; нельзя подбирать замену по порядку записей.
Для представителя строительного контроля используются реквизиты его собственной
организации из связи `signatories.org_id`, которая может отличаться от заказчика.

Реквизиты юридических лиц, СРО, ФИО, должности, номер НРС и основание полномочий
берутся из текущей БД. В строке представителя печатаются должность, сокращённое ФИО
и `order_doc`; в блоке подписи — то же лицо. Рукописная подпись остаётся пустой.
Файл приказа связывается через `order_attachment_id`; его наличие не заменяет
заполнение реквизитов `order_doc`.

Поля СРО, НРС и условных представителей не объявлены обязательными во всех случаях:
сам исходник содержит исключения и условия привлечения. Перед финалом агент
определяет применимость по сведениям пользователя и источникам, затем задаёт
нужную обязательность в `acts.fields`. Отсутствие значения не означает, что
исключение применимо. Неприменимые блоки исходного бланка остаются пустыми.

Для физического лица или ИП используйте индивидуальное переопределение
соответствующих полей `*_name` и других реквизитов; паспортные данные, ОГРНИП,
адрес проживания и иные сведения нельзя выдумывать или получать из ОГРН юрлица.
Для заказчика предусмотрено дополнительное поле `customer_individual`.

## Индивидуальные сведения

Сохранённые ключи `object_name` и `object_address` печатаются как `object.name`
и `object.address`. Адрес берётся из карточки объекта, индивидуальный текст
документа сохраняет приоритет. Город раздела не подменяет строительный адрес.

Даты подписания берутся из `act.date_signed`. В АОСР, АООК и АОУСИТО
`work_start` и `work_end` — индивидуальные даты работ в ISO `ГГГГ-ММ-ДД`,
печатаемые как `ДД.ММ.ГГГГ`. Общие `project.smr_start`/`smr_end` не используются.
`copies_count` — число экземпляров бумажного акта; для электронного выпуска
оно может оставаться пустым.

Материалы и документы качества, испытания, исполнительные схемы, технические
условия, ранее выпущенные АОСР, приложения и основания соответствия заполняются
по подтверждённым сведениям. Номер и дату каждого документа указывают явно;
если нужна ссылка на отдельный реестр, сам реестр должен быть подготовлен и связан.
Файлы связываются обычной командой `file-link --entity act --entity-id …`.
Наличие позиции в спецификации не доказывает её применение при этих работах.

В АООК поле `decision` содержит выбранные подпункты пункта 9 вместе с необходимыми
нагрузкой, условиями и разрешёнными последующими работами. Варианты исходника:
а) использование по назначению; б) использование с указанным процентом проектной
нагрузки; в) полное нагружение при условиях; г) последующие работы.
Шаблон не включает все разрешения по умолчанию. Процент нагрузки и условия не угадываются.

Индивидуальные значения сохраняются через `record-update` для `acts.fields`.
После правки БД документ формируется заново по новому пути. Значения из других
актов и учебных примеров автоматически не переносятся.

## Проверка выпуска

Базовые JSON проверяют заполнение основных полей, но не заменяют проверку
применимости конкретной формы, полномочий и содержания заключений.
Перед финалом агент сверяет утверждения бланка с фактическими сведениями,
проверяет применимость условных полей и внешний вид сформированного документа.
Строки для рукописных дат объединены для печати; исходные файлы не изменяются.
