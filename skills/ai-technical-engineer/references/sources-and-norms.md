# Исходные данные и нормативные основания

## Разбор исходников

Сначала составь перечень доступных РД и её редакций, спецификаций, изменений,
сведений об участниках и полномочиях, документов качества, журналов, испытаний
и исполнительных схем. Сопоставь его с уже сохранёнными записями. Недостающий
файл, неизвестный реквизит и отрицательный результат проверки — разные случаи.

Сохраняй оригиналы через `file-add`, связывай их через `file-link` с точными
объектами учёта. Один оригинал может использоваться в нескольких документах;
не создавай его копии как разные доказательства. При чтении используй
`read-document`; для таблиц и сканов проверяй изображения значимых страниц.
Учитывай листы, объединённые ячейки, переносы и единицы, а не только извлечённый
текст. Локаторы и SHA-256 сохраняй вместе с извлечёнными сведениями.

Для спецификации сверяй позиции, разделы таблицы, марки, количество, единицу,
примечания и редакцию. Заголовок группы не является номером каждой позиции.
Неизвестное количество не равно нулю. Примечание о дополнительном материале
нужно разобрать отдельно; оно не разрешает незаметно заменить проектное
количество или подтвердить поставку и монтаж.

Используй предварительный просмотр штатного импорта и его ключи источника.
Проверь, не создал ли прежний импорт приходы. Новую редакцию сначала сравни
через `spec-compare`; сохрани пользовательские уточнения и историю источников.
Если импорт предлагает подтвердить приход, решение принимай по поставочным
сведениям, а не по самому наличию строки в спецификации.

Документ качества связывай с соответствующим ресурсом и отдельно фиксируй
результат сверки: наименование, марка, партия/серийные номера, изготовитель,
даты и применимость документа. Наличие файла не означает `matches`, а
поступление материала не означает положительный входной контроль. При
изменении проверяемых реквизитов или файла повторно оцени актуальность проверки.

## Использование базы знаний

Прочитай ограничения в [описании базы знаний](../../../app/knowledge/README.md).
Локальные материалы могут быть подготовленными ИИ выдержками без проверенных
страниц оригинала. Успешная индексация не подтверждает точность, актуальность
или применимость нормы.

1. Определи назначение системы, вид работ, стадию строительства и особые
   условия объекта. Не выводи комплект нормативов из одного шифра раздела.
2. Проверь `knowledge-status`. Ищи по конкретной операции, затем прочитай
   полные фрагменты и связанные определения. Поиск использует основы слов,
   не морфологию; при отсутствии результата сократи запрос или фильтры.
3. Для решения проверь оригинал: шифр и редакцию, область применения,
   исключения, условия, таблицы и сноски. Для действующих требований при
   необходимости проверь официальную публикацию и изменения; не отправляй
   частные документы внешнему сервису без разрешения.
4. Сохрани основание решения: норматив, пункт, редакцию, источник, страницу
   оригинала при наличии, хеш, условие применения, статус сверки и открытые
   вопросы. ID поискового результата не заменяет эту информацию.

Для нового PDF норматива используй
[construction-norm-parser](../../construction-norm-parser/SKILL.md).
Не исправляй выдержки и `mandatory_level` в общей базе только для согласования
конкретного комплекта. Для нового или исправляемого бланка используй
[doc-template-generator](../../doc-template-generator/SKILL.md), сохраняя
оригинал и различия с ним.

## Определение состава ИТД

Рабочая таблица решений должна связывать: **работу → требование и условие →
документ/контроль → необходимые исходники → состояние готовности**. Используй
статусы «применимо», «неприменимо с основанием» и «недостаточно сведений».
В штатной матрице приложения есть `required` и `not_applicable`; открытые
вопросы сохраняй отдельно, не маскируя их вторым статусом.

Для систем автоматизации перечень приложения А СП 77 — отправная точка после
проверки области применения, а не готовый комплект на любой объект. Проверь
также исключения для специальных объектов. Различай защитную трубу для кабеля
и импульсную/командную трубную проводку: наличие первой само по себе не требует
испытаний второй. Формы для ВОЛС, сварки, прогрева, взрывозащиты, консервации
или частичной приёмки выбирай при наличии соответствующей работы и основания.

АОСР, освидетельствование участков сетей и другие дополнительные формы
обосновывай отдельно. Для скрытых работ устанавливай, что именно закрывается,
где, когда освидетельствуется и какие последующие работы разрешаются.
Не объявляй обычный заполнитель подтверждённой огнестойкой проходкой без
проектного решения и доказательств качества применённой системы.

Пример реестра заказчика используй как образец состава и оформления. Его даты,
названия документов, ошибки хронологии и практика приёмки не становятся
нормативными требованиями или фактами нового объекта.
